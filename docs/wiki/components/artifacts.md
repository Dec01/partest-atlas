# Контракт артефактов

**Публичный интерфейс пакета — это формат артефактов, а не классы.** Классы можно
переименовать в минорной версии; формат читает чужая программа, и его молчаливая правка
ломает её.

## Заголовок файла

Каждый артефакт — JSON, у которого пять полей заголовка идут раньше полезной нагрузки:

| Поле | Что значит |
|---|---|
| `version` | версия схемы (`SCHEMA_VERSION`) |
| `kind` | вид артефакта, ключ из `KINDS` |
| `scope` | пара «система, контур» — `{"system": …, "env": …}` |
| `collected_at` | локальное время сбора в ISO с точностью до секунды |
| `collector` | кто собрал; пустая строка допустима |

Версия и вид несутся **внутри файла**, а не выводятся из имени. Благодаря этому потребитель
говорит «артефакт старого формата» вместо того, чтобы упасть на отсутствующем поле, — и это
то, ради чего заголовок существует.

## Виды

`KINDS` отображает вид в имя файла. Вид пишется внутрь и проверяется при чтении.

| Вид | Файл |
|---|---|
| `db.schema` | `db_schema.json` |
| `db.effects` | `db_effects.json` |
| `bus.flow` | `bus_flow.json` |
| `containers.logs` | `container_logs.json` |
| `contract.openapi` | `openapi.json` |
| `specs.requirements` | `specs.json` |
| `ui.flow` | `ui_flow.json` |
| `load.profile` | `load.json` |
| `runner.history` | `runs.json` |

Неизвестный вид — ошибка в `filename()` на месте, а не отложенное падение при чтении.

`load.profile` пишет не этот пакет, а `partest-load`. Вид объявлен здесь, потому что формат
общий: место объявления и место записи — разные вещи.

## Область действия

Артефакт принадлежит паре **(система, контур)**. Система — самостоятельный продукт
заказчика; контур — среда, в которой он развёрнут. Раскладка на диске повторяет пару:

```text
atlas/<система>/<контур>/db_schema.json
```

`Scope` — замороженный датакласс со значениями по умолчанию `default/default`. Из-за них
однопроектный случай неотличим от прежнего: проект, ничего не знающий про системы и контуры,
продолжает работать, а артефакты первой версии читаются как `default/default` без миграции.

`Scope.from_env()` берёт `ATLAS_SYSTEM` и `ATLAS_ENV`; пустое значение равно умолчанию.

## Запись

`write()` кладёт заголовок и полезную нагрузку одним документом. Запись **атомарна**:
временный файл в том же каталоге, затем `os.replace`. Причина не в аккуратности — прогон
идёт в несколько процессов, и параллельный воркер не должен увидеть полузаписанный JSON,
а прерванный прогон не должен оставить битый артефакт.

`append_records()` дописывает записи в артефакт-список, схлопывая точные повторы по
сериализованной подписи. Существующее содержимое берётся, **только если совпал вид**: иначе
файл от другого сборщика молча слился бы с новым.

`read()` возвращает пустой словарь на отсутствующем или битом файле — не исключение. Карта
должна подниматься и на проекте, где ещё ничего не собрано.

## Проверка

`validate(doc)` возвращает список расхождений документа с контрактом и ничего не
поднимает: во что обходится расхождение, решает вызывающий.

Держится **отдельно от `read`**, и это не дублирование. `read` снисходителен нарочно —
битый файл он отдаёт пустым словарём, чтобы карта поднималась на проекте, где ещё ничего
не собрано. `validate` строг. Смешать их значит потерять одно из двух: либо карта
перестанет подниматься на пустом проекте, либо битый артефакт будет читаться как
сходящийся.

Проверка живёт здесь, а не у читающей программы, по той же причине, по которой формат
принадлежит этому пакету: повторённое у потребителя правило расходится молча, и
расхождение обнаруживается не там, где допущено.

Предъявляется командой `partest-atlas check` — см. [[howto/prepare-a-project]].

## Что из версии 1 читается, а что нет

Обещание «артефакты версии 1 читаются без миграции» верно **наполовину**, и разница
выяснилась при переносе первого сборщика (2026-09-25), когда артефакты прототипа сверили
с контрактом.

| поле | версия 1 | версия 2 | читается ли |
|---|---|---|---|
| `scope` | отсутствует | `{system, env}` | да — `Scope.from_doc` даёт `default/default` |
| `collector` | отсутствует | строка | ключа нет — `validate` назовёт это расхождением |
| `kind` | `db_schema` | `db.schema` | **нет** — имя вида изменилось, точка вместо подчёркивания |

То есть документ версии 1 **читается** (`read` отдаст его содержание), но проверку
контракта не проходит. Это не дефект проверки: вид `db_schema` действительно не из
набора, и читающая программа, встретив его, не знает, что перед ней.

Практическое следствие для проекта, который собирал артефакты прототипом: их надо
**снять заново** этим пакетом, а не чинить руками. Снятие дешевле правки, и только оно
даёт честные `collected_at` и `collector`.

## Красная линия

Изменение формата требует повышения `SCHEMA_VERSION` **и** записи в `CHANGELOG.md` всех
участников. Владелец формата — этот пакет; читают его `partest-load` и сервер карты.
В одиночку формат не меняется.
