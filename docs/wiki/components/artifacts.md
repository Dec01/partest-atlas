# Контракт артефактов

**Публичный интерфейс пакета — это формат артефактов, а не классы.** Классы можно
переименовать в минорной версии; формат читает чужая программа, и его молчаливая правка
ломает её.

Имена модуля `partest_atlas.artifacts` из `__all__` — тоже контракт: `KINDS`,
`PAYLOAD_KEYS`, `SCHEMA_VERSION`, `STATES`, `RUN_ID_ENV`, `DEFAULT_SCOPE_KEY`, `Scope`,
`SCOPE_RULE_RU`/`SCOPE_RULE_EN`, `valid_scope_part`, `Inspection`, `read`, `write`,
`append_records`, `keep_last_runs`, `redact_payload`, `validate`, `inspect`,
`discover_scopes`, `scope_of`, `kind_of`, `filename`, `run_label`. Меняются только с записью
в `CHANGELOG.md`.

## Заголовок файла

Каждый артефакт — JSON, у которого пять полей заголовка идут раньше полезной нагрузки:

| Поле | Что значит |
|---|---|
| `version` | версия схемы (`SCHEMA_VERSION`) |
| `kind` | вид артефакта, ключ из `KINDS` |
| `scope` | пара «система, контур» — `{"system": …, "env": …}` |
| `collected_at` | время сбора в ISO с поясом; по умолчанию — сейчас, `write(..., collected_at=…)` — заданное (строка как есть, `datetime` — ISO) |
| `collector` | кто собрал; пустая строка допустима |

Версия и вид несутся **внутри файла**, а не выводятся из имени. Благодаря этому потребитель
говорит «артефакт старого формата» вместо того, чтобы упасть на отсутствующем поле, — и это
то, ради чего заголовок существует.

## Виды

`KINDS` отображает вид в имя файла. Вид пишется внутрь и проверяется при чтении.

| Вид | Файл |
|---|---|
| `db.schema` | `db_schema.json` |
| `db.effects` | `db_effects.json` |
| `bus.flow` | `bus_flow.json` |
| `containers.logs` | `container_logs.json` |
| `contract.openapi` | `openapi.json` |
| `specs.requirements` | `specs.json` |
| `ui.flow` | `ui_flow.json` |
| `load.profile` | `load.json` |
| `runner.history` | `runs.json` |

Неизвестный вид — ошибка в `filename()` на месте, а не отложенное падение при чтении.
Обратное — `kind_of(path)`: вид по имени файла, `None` — имя не из контракта.

## Ключ полезной нагрузки

`PAYLOAD_KEYS` — под каким ключом лежат записи вида; их число — размер артефакта.
Потребитель не держит свою таблицу.

| Вид | Ключ |
|---|---|
| `db.schema` | `databases` |
| `db.effects`, `bus.flow` | `records` |
| `containers.logs` | `containers` |
| `contract.openapi` | `operations` |
| `specs.requirements` | `requirements` |
| `ui.flow` | `links` |
| `runner.history` | `runs` |

`load.profile` в таблице нет: формат вида не согласован, и его пока никто не пишет.

Аддитивные поля схемы 2, появившиеся без смены версии (`CHANGELOG.md`, Unreleased):

- `db.effects` — `schema` рядом с `table`: таблица — пара (схема, имя).
- `db.schema` — `schema` у цели внешнего ключа (`fk`).
- `db.effects`, `bus.flow` — `run: {id, startedAt}` в каждой записи: метка прогона
  (`run_label()`: `ATLAS_RUN_ID`, если задан, иначе случайная; одна на процесс). У
  `db.effects` в режиме `test` с `db_effects.phases: true` — ещё `phase`:
  `setup`/`call`/`teardown`. Записи без ключей — снятые раньше; читаются как раньше.
- `containers.logs` — `logs: [{name, read, lines}]` и `stats.read`/`unread`/`lines`:
  «журнал не прочитан» (`read: false`) отличим от «прочитан, связей нет». `containers` —
  по-прежнему только контейнеры с находками.
- `contract.openapi` — `info`, `source`, `services`, `service` у операции
  ([[components/collect]], «Несколько служб»).
- `ui.flow` — `screen` нормализован: `#/orders/42?tab=1` → `/#/orders/{id}`.

Что внутри `runner.history` и что значит срез покрытия в его записях — [[components/history]].

`load.profile` пишет не этот пакет, а `partest-load`. Вид объявлен здесь, потому что формат
общий: место объявления и место записи — разные вещи.

## Область действия

Артефакт принадлежит паре **(система, контур)**. Система — самостоятельный продукт
заказчика; контур — среда, в которой он развёрнут. Раскладка на диске повторяет пару:

```text
atlas/<система>/<контур>/db_schema.json
```

`Scope` — замороженный датакласс со значениями по умолчанию `default/default`. Из-за них
однопроектный случай неотличим от прежнего: проект, ничего не знающий про системы и контуры,
продолжает работать.

`Scope.from_env()` берёт `ATLAS_SYSTEM` и `ATLAS_ENV`; пустое значение равно умолчанию.

**Имя области — имя каталога, и правило его здесь** (`valid_scope_part`, договор
`atlas-config`): латиница, цифры, `.`, `_`, `-`; не `.`, не `..` и без `..` внутри — то же,
что у читающей программы. `Scope(...)` с другим именем — `ValueError`; `Scope.from_env()` —
`ValueError` с именем переменной, без значения. `validate` называет негодную область в
файле, `discover_scopes` и `scope_of` такие каталоги пропускают.

**Область в файле обязана совпадать с каталогом.** `validate(doc, scope=…)`, `inspect` и
`partest-atlas check` сверяют их: файл, перенесённый в каталог другого контура, —
расхождение, а не годные данные. `scope_of(path)` — область по раскладке
`…/<система>/<контур>/<файл>`. `discover_scopes(artifacts_dir)` — области, где лежит хотя
бы один артефакт известного вида, по именам каталогов.

## Запись

`write()` кладёт заголовок и полезную нагрузку одним документом. Запись **атомарна**:
временный файл в том же каталоге, затем `os.replace`. Причина не в аккуратности — прогон
идёт в несколько процессов, и параллельный воркер не должен увидеть полузаписанный JSON,
а прерванный прогон не должен оставить битый артефакт.

**Маскировка при записи.** `write()` прогоняет каждую строку полезной нагрузки — значения и
ключи — через `partest.redact.redact_text` (`redact_payload`): всё, что попадает в артефакт,
проходит `partest.redact`. Имена таблиц, путей и топиков она не меняет; меняет то, что
выглядит секретом (`password=…`, `Bearer …`, `user:pw@host`) — в описаниях спецификации,
значениях по умолчанию колонок, находках в журналах, `nodeid`.

`append_records()` дописывает записи в артефакт-список, схлопывая точные повторы по
сериализованной подписи (новые записи маскируются до сравнения). `keep_runs` больше нуля —
остаются записи последних стольких прогонов по `run.startedAt` (`keep_last_runs`;
сравнивается время с поясом, а не текст; записи без метки уходят первыми). Существующее содержимое берётся, **только если совпал вид**: иначе
файл от другого сборщика молча слился бы с новым.

Дописывание — чтение, слияние и атомарная замена **без блокировки**. Полузаписанный файл
никто не увидит, но два процесса, дописывающие один файл одновременно, потеряют записи
одного из них. Поэтому под pytest-xdist `db_effects` и `bus_flow` пишут только с
контроллера; `ui_flow` пишет файл целиком с каждого воркера, и под xdist в нём остаются
связи последнего.

`read()` возвращает пустой словарь на отсутствующем или битом файле — не исключение. Карта
должна подниматься и на проекте, где ещё ничего не собрано.

## Проверка

`validate(doc)` возвращает список расхождений документа с контрактом и ничего не
поднимает: во что обходится расхождение, решает вызывающий. Тексты расхождений — для
человека и по-русски; по-английски — только под командой с `--lang en` или английской
локалью ([[components/collect]], «Язык вывода»). Машине сверять их текст не следует.

Держится **отдельно от `read`**, и это не дублирование. `read` снисходителен нарочно —
битый файл он отдаёт пустым словарём, чтобы карта поднималась на проекте, где ещё ничего
не собрано. `validate` строг. Смешать их значит потерять одно из двух: либо карта
перестанет подниматься на пустом проекте, либо битый артефакт будет читаться как
сходящийся.

Проверка живёт здесь, а не у читающей программы, по той же причине, по которой формат
принадлежит этому пакету: повторённое у потребителя правило расходится молча, и
расхождение обнаруживается не там, где допущено.

`validate(doc, kind=…, scope=…)` сверяет ещё вид документа с видом файла и область с
каталогом. `partest-atlas check` передаёт вид по имени каждого файла и область — для
файлов, найденных в названном каталоге по раскладке `<каталог>/<система>/<контур>/<файл>`;
у файла, названного напрямую, область не сверяется: по пути не сказать, чья она.

Предъявляется командой `partest-atlas check` — см. [[howto/prepare-a-project]].

## Решение об артефакте: `inspect`

`inspect(path, kind, *, scope=None)` читает файл и возвращает `Inspection` — состояние
машинным кодом (`STATES`):

| Состояние | Когда |
|---|---|
| `ok` | прочитан и сходится; документ — в `doc`, число записей — в `records` |
| `missing` | файла нет — законное состояние проекта, который этого не собирал |
| `broken` | файл есть, но не JSON-объект (или пуст) |
| `newer` | схема новее известной — читать вслепую нельзя |
| `invalid` | контракт не сходится: схема 1, чужой вид, чужая область, кривая шапка |

`doc` заполнен только при `ok`. Нет ключа полезной нагрузки — `ok` с предупреждением в
`warnings`. Своя граница читаемых версий у потребителя (сервер, знающий только схему 2)
— его дело: `inspect` судит по `SCHEMA_VERSION` этого пакета.

## Версия 1 не годится как данные

Прежнее обещание «артефакты версии 1 читаются без миграции» противоречило `validate` и
снято: правило одно — **документ схемы 1 контракт не проходит**, его снимают заново.
`validate` говорит это прямо («старше схемы 2: снимите артефакт заново»), `inspect` даёт
`invalid`. Разница выяснилась при переносе первого сборщика (2026-09-25), когда артефакты
прототипа сверили с контрактом.

| поле | версия 1 | версия 2 | читается ли |
|---|---|---|---|
| `scope` | отсутствует | `{system, env}` | да — `Scope.from_doc` даёт `default/default` |
| `collector` | отсутствует | строка | ключа нет — `validate` назовёт это расхождением |
| `kind` | `db_schema` | `db.schema` | **нет** — имя вида изменилось, точка вместо подчёркивания |

То есть документ версии 1 **читается** (`read` отдаст его содержание, `Scope.from_doc` —
`default/default`), но проверку контракта не проходит. Это не дефект проверки: вид `db_schema` действительно не из
набора, и читающая программа, встретив его, не знает, что перед ней.

Практическое следствие для проекта, который собирал артефакты прототипом: их надо
**снять заново** этим пакетом, а не чинить руками. Снятие дешевле правки, и только оно
даёт честные `collected_at` и `collector`.

## Красная линия

Изменение формата требует повышения `SCHEMA_VERSION` **и** записи в `CHANGELOG.md` всех
участников. Владелец формата — этот пакет; читают его `partest-load` и сервер карты.
В одиночку формат не меняется.
