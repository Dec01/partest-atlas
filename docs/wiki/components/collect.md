# Команда `collect`

Контракт OpenAPI, схема базы и связи из журналов контейнеров не требуют прогона тестов.
Раньше проект снимал их своим кодом: скачать документ, вызвать `openapi.build`, записать
артефакт. Теперь это одна команда на источник.

```bash
partest-atlas collect openapi [--service ИМЯ]
partest-atlas collect db-schema
partest-atlas collect container-logs
```

## Общее

| Ключ | Что значит |
|---|---|
| `--root КАТАЛОГ` | откуда искать `atlas.yaml` (вверх по каталогам) и где лежит `confpartest.py`; по умолчанию текущий каталог, а `confpartest.py` — в каталоге найденного `atlas.yaml` |
| `--system`, `--env` | область поверх `ATLAS_SYSTEM` / `ATLAS_ENV`; по умолчанию `default` |
| `--json` (до подкоманды) | отчёт машине: `kind`, `path`, `scope`, `stats`, у `openapi` ещё `info` и `source` |
| `--lang ru\|en` (до подкоманды) | язык вывода — см. ниже |

Запись — `artifacts.write` в `<artifacts_dir>/<система>/<контур>/`, и только туда. Часть
области — имя каталога: значение с `..`, `/`, `\` или `:` отклоняется, иначе запись ушла бы
за пределы каталога артефактов.

Каталог проекта ставится в начало `sys.path`: `database.connect` и `container_logs.source`
называют модули проекта, а у установленной команды текущего каталога в пути нет.

**Коды:** `0` — артефакт записан, в stdout одна строка: вид, сводка, путь. `2` — снять не
удалось: **одна строка** в stderr (`partest-atlas collect <что>: причина`), артефакт не
пишется, прежний не трогается. Текст ошибки проходит `partest.redact` — в сообщениях
драйвера бывают адрес и имя пользователя, а stderr уходит в журнал конвейера.

## `collect openapi`

Источник — `confpartest.swagger_files` проекта, то же место, откуда покрытие считает
partest:

```python
swagger_files = {
    "магазин": ["local", "docs/openapi.yaml"],          # путь — от каталога confpartest.py
    "склад":   ["url", "https://host/v3/api-docs"],     # адрес — в окружении проекта
}
```

- `confpartest.py` загружает `partest.load_confpartest` — это **импорт кода проекта**, как
  при прогоне pytest. Загруженный модуль обязан быть `confpartest.py` из каталога проекта:
  `confpartest`, уже импортированный или найденный раньше по `sys.path`, — отказ, а не чужой
  контракт без предупреждения.
- Вид источника — `local`, `file`, `path` или `url` в любом регистре, как принимает partest.
- Локальный путь — от каталога `confpartest.py`, а не от текущего.
- Адрес читается клиентом `partest.httpx_client` под политикой TLS проекта
  (`confpartest.tls_verify`, `PARTEST_TLS_VERIFY`); `user:password@` уходит в заголовок, а не
  в адрес запроса. Ответ 4xx/5xx, тайм-аут, недоступный хост, непринятый сертификат — код 2,
  в сообщении адрес без учётных данных и строки запроса.
- Без `--service` спецификация должна быть одна: выбрать первую из нескольких значило бы
  снять не тот контракт и не сказать об этом. Артефакт `contract.openapi` у области один —
  несколько служб разводятся по системам (`--system`).
- Документ — JSON или YAML, объект с ключом `openapi` или `swagger`; иначе отказ (типичный
  случай — адрес отдал ошибку в JSON или страницу входа).

В артефакт, кроме операций и `stats`, пишутся:

| Ключ | Содержание |
|---|---|
| `info` | `{title, version}` из документа, строками; не объявлено — `null` |
| `source` | `{service, type, location}`: `type` — `local` или `url`; адрес без `user:password@`, строки запроса и якоря и через `partest.redact.redact_text`; локальный путь — как объявлен, не разрешённый |

Обе записи аддитивны: `SCHEMA_VERSION` остаётся 2. `info` пишет и `openapi.build()` из кода.

## `collect db-schema`

Существующий `db_schema.write()` из командной строки. Раздел `database` в `atlas.yaml`:

| Ключ | Что значит |
|---|---|
| `connect: "модуль:функция"` / `dsn_env` | соединение, как и раньше; без обоих — `DATABASE_URL` |
| `schemas` | список схем; строка — одна схема; нет ключа — `public`; **`auto`** — все несистемные схемы, какие видит база (кроме `pg_catalog`, `information_schema`, `pg_*`) |
| `key` | ключ базы в артефакте; по умолчанию `primary`, как было |
| `label`, `exclude`, `count_rows` | как раньше |

**В выбранных схемах нет ни одной таблицы — ошибка**, а не пустой артефакт: после переезда
таблиц в другую схему сборщик молча писал «таблиц нет». Сообщение называет схемы и советует
`schemas: auto`.

### Только чтение держит база

Красная линия «базы только на чтение» держится механизмом, а не тем, что запросы написаны
как `SELECT`. Каждый блок запросов — `adapters.postgres.read_only(conn)`:

1. `BEGIN TRANSACTION READ ONLY` — при autocommit это и есть блок; если драйвер уже открыл
   транзакцию, PostgreSQL отвечает предупреждением;
2. `SET TRANSACTION READ ONLY` — текущая транзакция только на чтение, кто бы её ни открыл;
3. `SHOW transaction_read_only` обязан ответить `on`, иначе `NotReadOnly` и ни одного запроса;
4. на выходе `ROLLBACK`.

Только уровень транзакции, не сессии: настройка сессии пережила бы нас на соединении,
которое проект отдал из своего пула, и его следующая запись упала бы на чужом запрете.
Вторая линия — каждый запрос `db_schema` до отправки проходит
`partest.sideeffects.assert_read_only_sql`. Снимки плагина `db_effects` идут в такой же
транзакции.

## `collect container-logs`

Только при объявленном `container_logs.source: "модуль:функция"` — функция проекта отдаёт
словарь «имя контейнера → текст журнала». Без источника, без включённых правил
(`container_logs.rules`) или если источник вернул не словарь — код 2: пустой артефакт
выглядел бы как «журналы прочитаны, связей нет». Словари для правил `known_only` — из уже
снятых `db.schema` и `bus.flow` той же области.

Источник может вернуть для контейнера `None` — журнал не достали. В артефакте рядом с
`containers` (только контейнеры с находками, как раньше) лежит `logs`:
`[{name, read, lines}]` на каждый названный контейнер, и в `stats` — `read`, `unread`,
`lines`. Так «не прочитан» (`read: false`) отличим от «прочитан, связей нет».

## Язык вывода

`--lang ru|en` важнее локали. Без ключа — первая непустая из `LC_ALL`, `LC_MESSAGES`, `LANG`,
затем локаль процесса (на Windows переменных обычно нет). `ru*` и `Russian_*` — русский,
другой язык — английский, `C`/`POSIX` и неопределимая — русский, как было до ключа.

Переводятся справка, вывод `check`, `show`, `wrap` и `collect`, тексты расхождений
`artifacts.validate` и сообщения об ошибках конфигурации, соединения, журналов и обёртки.
Ключи `--json` не переводятся. Плагины pytest печатают по-русски.

Язык переключает только команда и только на время вызова: код, который зовёт функции пакета
сам, получает русский, как раньше (`partest_atlas.lang`).
