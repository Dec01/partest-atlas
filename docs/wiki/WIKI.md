# WIKI.md — схема документации

Здесь описано, **как устроена** документация этого репозитория. Знания нет — оно на страницах.
Читается один раз перед правкой доков; в обычной работе не нужен.

## Схема

Три слоя — неизменяемые источники (вне репозитория),
производное знание (`docs/wiki/`), конвенции (этот файл плюс `AGENTS.md`). Каталоги —
`concepts` (почему), `components` (что есть), `howto` (как сделать), `decisions` (почему
именно так).

## Что своё у этого репозитория

**Публичный интерфейс — не классы, а формат артефактов.** Отсюда следует необычное для
библиотеки правило: страница `components/artifacts` важнее любой другой и сверяется с кодом
в первую очередь. Артефакт читает чужая программа, и расхождение документа с форматом
дороже расхождения документа с реализацией сборщика.

**Формат — контракт между пакетами.** Владелец формата — этот пакет; читают его
`partest-load` и сервер карты. Изменение формата без повышения `SCHEMA_VERSION` и записи
в `CHANGELOG.md` всех участников — дефект.

**Колеса с документами пока нет.** `ships_in_wheel` в frontmatter не используется: в отличие
от `partest`, этот пакет документы в дистрибутив не везёт. Появится такая сборка — правило
придёт из `partest` вместе с инструментом, а не будет придумано здесь заново.

## Что проверяется автоматически

Отсутствующий frontmatter, страницы, новее которых стал код (`sources:` против `verified:`),
битые ссылки, литералы версий, приватные данные, страницы, потерянные мимо `index.md`.
