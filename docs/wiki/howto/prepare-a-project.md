# Как подготовить проект

Эта страница отвечает на один вопрос: **что должно быть сделано в проекте с автотестами,
чтобы по нему можно было построить карту.** Порядок здесь — порядок работ, а не
оглавление.

Читающая программа — отдельная, этот пакет её не импортирует и без неё полностью
работоспособен. Поэтому подготовка проекта заканчивается там, где на диске появляются
артефакты: всё, что с ними делают дальше, — не забота проекта.

## Коротко

| Шаг | Что делает проект | Чем проверить |
|---|---|---|
| 1 | ставит пакет | `partest-atlas --help` отвечает |
| 2 | кладёт `atlas.yaml` в корень | сборщики перестают требовать аргументов |
| 3 | объявляет доступы в окружении | сборщик пишет артефакт, а не «источник недоступен» |
| 4 | включает нужные сборщики | в выводе прогона появляются их строки |
| 5 | прогоняет тесты как обычно | в `artifacts_dir` появляются файлы |
| 6 | **проверяет артефакты** | `partest-atlas check <каталог>` → код 0 |

Шаг 6 не украшение. Формат читает чужая программа, и у неё нет способа сказать вам, что
вы пишете мимо контракта, — она просто построит неверную картину.

## 1. Установка

```bash
pip install partest-atlas
```

Драйверы источников вынесены в extras намеренно: их лицензии и их вес не должны
навязываться проекту, которому нужен только контракт или разбор спецификаций.

```bash
pip install "partest-atlas[postgres]"   # схема и эффекты в БД
pip install "partest-atlas[kafka]"      # поток шины
pip install "partest-atlas[ui]"         # поток UI
pip install "partest-atlas[all]"        # всё сразу
```

Проверка, что установка дала работающую команду, а не только запись в метаданных:

```bash
partest-atlas --help
```

## 2. `atlas.yaml` — единственный проектный файл

Весь проектный смысл живёт здесь. Код сборщиков про ваш проект не знает ничего, и это
главное свойство: **перенос сбора на другой проект — это новый `atlas.yaml`, а не новый
код.** Если ради второго проекта пришлось править сборщик, значит проектное знание
протекло в пакет, и это дефект пакета.

Минимальный файл:

```yaml
project:
  name: Имя системы          # попадает в артефакты как имя, не как идентификатор
  api_prefix: /api/v1        # по нему сборщик контракта отделяет своё от чужого

artifacts_dir: atlas         # куда складывать; относительно корня проекта
```

Дальше — по разделу на источник. Разделы необязательны: нет раздела — нет сборщика,
и это нормальное состояние, а не ошибка. Набор разделов задаёт, **что вы готовы
показать**, и ничего не обещает сверх этого.

## 3. Доступы — в окружении, не в файле

`atlas.yaml` лежит в репозитории и попадает в историю. Адреса, логины и пароли туда не
пишутся: файл называет **имя переменной**, значение приходит из окружения.

Это не только про секреты. Один и тот же `atlas.yaml` должен работать у разработчика на
машине и на сборочном конвейере — отличаются они окружением, а не файлом.

## 4. Включение сборщиков

Сборщики по умолчанию **молчат**. Обычный прогон тестов не платит за их присутствие
ничего — ни временем, ни обращениями к источникам. Включается каждый своей переменной
окружения; пока она не выставлена, плагин загружен и бездействует.

Причина такая: карта — не то, ради чего проект гоняет тесты. Сбор, который замедляет
обычный прогон или роняет его, когда источник недоступен, перестанут включать, и карта
устареет. Поэтому **недоступный источник не роняет прогон** — он оставляет запись о том,
что источника не было.

Из этого следует обязанность, о которой легко забыть: сборщик обязан различать
**«источника нет»** и **«я настроен неправильно»**. Оба не валят прогон, но это разные
новости, и одинаковая строка про них стоила одному проекту полдня: сборщик до конца
прогона сообщал «источник недоступен», тогда как на самом деле ему передали ключ,
которого он не понимает.

## 5. Прогон

Отдельной команды нет — сбор идёт **вместе с обычным прогоном тестов**, потому что
половина наблюдений существует только во время него: какой тест какую кнопку нажал, что
после этого поехало по шине, какие строки изменились в базе.

```bash
ATLAS_DB_EFFECTS=1 ATLAS_BUS_FLOW=1 pytest
```

Наблюдения, которые прогона не требуют (схема базы, контракт, спецификации), снимаются
отдельно и живут дольше: их не нужно пересобирать на каждый прогон.

## 6. Что появляется на диске

Один вид — один файл. Имя файла задано контрактом и его нельзя выбрать:

| Вид | Файл |
|---|---|
| `db.schema` | `db_schema.json` |
| `db.effects` | `db_effects.json` |
| `bus.flow` | `bus_flow.json` |
| `containers.logs` | `container_logs.json` |
| `contract.openapi` | `openapi.json` |
| `specs.requirements` | `specs.json` |
| `ui.flow` | `ui_flow.json` |
| `load.profile` | `load.json` |
| `runner.history` | `runs.json` |

Раскладка — `<artifacts_dir>/<система>/<контур>/<файл>`. Система и контур берутся из
`ATLAS_SYSTEM` и `ATLAS_ENV`, по умолчанию оба `default`, и тогда однопроектный случай
выглядит как простой каталог. Раскладка нужна, когда карта сводит **несколько** систем
или один продукт на нескольких контурах: без неё артефакты второго контура молча затрут
первый.

У каждого файла одинаковая шапка: `version`, `kind`, `scope`, `collected_at`,
`collector`. Всё остальное — содержание вида.

## 7. Проверка — обязательный шаг, а не необязательный

```bash
partest-atlas check atlas
```

Команда отвечает:

- код **0** — артефакты сходятся с контрактом;
- код **2** — нашлись расхождения, и каждое названо;
- код **1** — посмотреть не удалось (путь не тот, файлов нет).

Коды 1 и 2 разделены намеренно. Сведение их в один — обычный способ выдать отсутствие
проверки за пройденную: «ничего не нашли» и «нечего было смотреть» выглядят одинаково.
По той же причине команда печатает **число прочитанных файлов**: «чисто» без числа
неотличимо от «смотреть было не на что».

Посмотреть, что внутри, не читая JSON глазами:

```bash
partest-atlas show atlas
```

## Что проект получает взамен

Набор версионированных файлов, которые:

- **не зависят от читающей программы** — их формат принадлежит этому пакету, и он
  единственное, что стороны обязаны соблюдать;
- **переживают прогон** — предупреждение в выводе pytest не доживает до конца сессии,
  запись в артефакте доживает;
- **сравнимы между прогонами** — у каждого есть время съёмки и версия схемы.

## Чего ещё нет

Говорить об этом прямо дешевле, чем обещать. Сборщики в пакет **ещё не перенесены** —
перенос идёт из проекта-прародителя по одному, каждый со своим артефактом и своими
проверками. Готовы: контракт артефактов, проверка контракта и команда. Состояние —
[[status]].

Пока перенос не закончен, шаги 4 и 5 выполняются кодом проекта-прародителя, а шаги 1, 2,
6 и 7 — уже этим пакетом.
