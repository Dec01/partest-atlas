# partest-atlas

Агент сбора для **«Вехи»** — карты системы, раскрашенной тестами.

Пакет снимает наблюдения на прогоне автотестов и рядом с ним, складывает их в
версионированные JSON-артефакты и на этом останавливается. Выводы из артефактов делает
сервер «Веха» — отдельная программа, которая этот пакет не импортирует и не требуется ему
для работы.

**PyPI:** `partest-atlas` · **Лицензия:** MIT

```bash
pip install partest-atlas
```

## Зачем разделено так

Агент — измерительные приборы: он записывает, что клик ушёл в такой-то запрос, что за тест
изменилось в счётчиках таблиц, какие смещения были у топиков до и после. Каждое наблюдение
само по себе бесполезно.

Сервер — тот, кто из наблюдений делает вывод. Например, задумано различать «в таблицу
писал не API, а консьюмер»; данных для этого агент пока не даёт — признак `afterWrite` в
`bus.flow` значит только «часы HTTP видели хоть одну пишущую запись» (см.
`docs/wiki/proposals.md`, предложение B).

Поэтому агент открыт: он ходит в базу, шину и логи заказчика, и его должна иметь
возможность прочитать служба безопасности. Защищать здесь нечего — ценность не в сборе.

## Что внутри

```text
partest_atlas/
  artifacts.py      контракт артефактов: version, kind, scope, атомарная запись
  collect/          сборщики: схема БД, эффекты в БД, шина, логи контейнеров,
                    контракт OpenAPI, требования из спецификаций, поток UI
  adapters/         доступ к чужим системам: db/ bus/ containers/ ci/ tests/ contract/
  plugins/          pytest-плагины (entry point pytest11), молчат без переменных окружения
  wrap.py           `partest-atlas wrap -- <любая команда>` — запуск чужого прогона с его кодом возврата
```

## Три уровня внедрения

| Уровень | Что делает проект | Что даёт |
|---|---|---|
| **Обёртка** | `partest-atlas wrap -- <своя команда прогона>` | пока только запуск с честным кодом возврата; снимки до и после задуманы, но в команде не сделаны |
| **Агент** | ставит пакет, выставляет `ATLAS_*` | наблюдения прогона pytest; эффекты в БД — поштучно для немногих тестов под замером, иначе на весь прогон |
| **Маркеры** | `@pytest.mark.db_effects` | точный отбор тестов под замер эффектов в БД |

`wrap` на Windows запускает `.cmd`/`.bat` (`npm` из `PATH`, `.\gradlew` из проекта) через
системный `cmd.exe` (`%SystemRoot%\System32`, не `COMSPEC`), но не любой ценой:

- аргумент с `% " & | < > ^`, переводом строки или NUL такому скрипту **не передаётся** —
  команда отклоняется с кодом 127, потому что скрипт снимает кавычки сам (`%~1`) и `&`
  становится второй командой. Нужен такой аргумент — зовите интерпретатор напрямую
  (`node …`, `java …`, `python …`);
- голое имя ищется только по абсолютным записям `PATH`. Нашлось лишь в текущем каталоге
  или по относительной записи `PATH` — отказ с просьбой назвать путём: `.\gradlew`, а не
  `gradlew`.

Точная граница — `docs/wiki/components/overview.md`.

Плагины подключаются через `pytest11` и **молчат, пока не выставлена соответствующая
переменная окружения** — обычный прогон не платит за их присутствие ничего.

## Раскладка артефактов

```text
atlas/<система>/<контур>/db_schema.json
atlas/<система>/<контур>/ui_flow.json
...
```

Заголовок каждого файла несёт `version`, `kind`, `scope` и время сбора, поэтому потребитель
может честно сказать «артефакт старого формата», а не упасть на отсутствующем поле.

## Отношение к partest

В метаданных `partest-atlas` зависит от [`partest`](https://pypi.org/project/partest/)
(`partest>=1.8`), но **код пакета partest не импортирует**: сопоставление URL с шаблоном
OpenAPI, редактирование секретов и проверка «только `SELECT`» из partest пока не
подключены. Обратной зависимости нет и не будет: `partest` про `partest-atlas` не знает.

Маркера трассируемости требований (`@pytest.mark.req`) нет ни здесь, ни в partest. По
замыслу ему место в partest — он полезен и без карты, — но сделан он не был.
